## 1. Project Motivation & Academic Positioning

### Q1: What is the core objective of CogniCNC?

CogniCNC is an Industry 4.0 software platform that integrates:

## 2. Machine Learning Pipeline & Dataset

### Q3: Explain the UCI AI4I 2020 Dataset schema.
**Answer:**
The dataset consists of **10,000 tool records** representing synthetic CNC milling data reflecting real-world industrial behavior:
- **6 Model Input Features**:
  1. `Type`: Product quality variant (`L` = Low 50%, `M` = Medium 30%, `H` = High 20%).
  2. `Air temperature [K]`: Ambient factory temperature (~300 K).
  3. `Process temperature [K]`: Cutting zone temperature generated by friction (~310 K).
  4. `Rotational speed [rpm]`: Spindle speed (1168 to 2886 RPM).
  5. `Torque [Nm]`: Spindle torque load (3.8 to 76.6 Nm).
  6. `Tool wear [min]`: Cumulative cutter contact duration (0 to 253 min).
- **Target Feature**: `Machine failure` (Binary: 0 for healthy, 1 for failure, ~3.39% positive class imbalance).
- **5 Failure Modes**: `TWF` (Tool Wear Failure), `HDF` (Heat Dissipation Failure), `PWF` (Power Failure), `OSF` (Overstrain Failure), `RNF` (Random Failure).

### Q4: Why are simulated fields like Vibration and Power excluded from the ML model input?
**Answer:**
**Data Schema Integrity Rule**: Machine learning models can only be evaluated on the exact feature space on which they were trained. The UCI AI4I dataset contains 6 specific features. Our physics simulator models extra real-world signals (`vibration_mm_s`, `power_kw`) for operator monitoring and rule-based checks, but these are **never fed into the scikit-learn ML pipeline** to prevent feature misalignment and schema errors.

### Q5: Why choose Random Forest over Deep Learning (e.g., LSTM / CNN)?
**Answer:**
1. **Tabular Feature Efficacy**: Tree-based ensembles (Random Forest, Gradient Boosting) consistently outperform deep neural networks on tabular datasets with under 50,000 rows (supported by *Grinsztajn et al., NeurIPS 2022*).
2. **Class Imbalance Resilience**: Random Forest supports balanced sub-sampling (`class_weight='balanced'`), allowing robust performance on the 3.4% failure minority class.
3. **Inference Latency & Determinism**: Random Forest executes inference in `< 2 ms` on standard CPU hardware without GPU acceleration, making it suitable for edge gateway deployment.
4. **Feature Attribution & Explainability**: Decision trees yield direct Gini impurity reduction scores and tree traversal paths for XAI explanations.

### Q6: Why use Isolation Forest for Anomaly Detection?
**Answer:**
Supervised models only recognize failure modes present in the training labels. **Isolation Forest** is an unsupervised algorithm that isolates anomalies by randomly partitioning feature values. Because anomalies require fewer random splits to isolate in hyperspace, they produce shorter tree path lengths. This enables CogniCNC to catch novel, unforeseen machine behaviors (e.g., sudden thermal spikes or torque anomalies) even if the supervised model has never seen that specific failure pattern before.

## 3. Industrial Engineering & OEE Analytics

### Q7: How is OEE calculated in CogniCNC?
**Answer:**
OEE (Overall Equipment Effectiveness) is calculated as:
$$\text{OEE} = \text{Availability} \times \text{Performance} \times \text{Quality}$$

1. **Availability ($A$)**:
   $$A = \frac{\text{Operating Time}}{\text{Planned Production Time}} = \frac{\text{Uptime}}{\text{Uptime} + \text{Downtime}}$$
2. **Performance ($P$)**:
   $$P = \min\left(1.0, \frac{\text{Total Parts Produced} \times \text{Ideal Cycle Time (sec)}}{\text{Operating Time (sec)}}\right)$$
   *(Ideal cycle times: Turning = 120s, Milling = 150s, Drilling = 90s, Grinding = 180s, Inspection = 10s)*
3. **Quality ($Q$)**:
   Heuristic quality rate derived from machine health:
   - `RUNNING` (Normal): $99.0\%$
   - `WARNING` (Degraded): $95.0\%$
   - `FAULT` / `MAINTENANCE`: $0.0\%$ (production halted)

### Q8: How is the production line bottleneck identified?
**Answer:**
In a sequential manufacturing line, the bottleneck is defined by **Theory of Constraints (Goldratt)** as the machine with the lowest throughput rate ($\text{parts/minute}$). CogniCNC calculates:
$$\text{Throughput}_i = \frac{\text{Total Parts Produced}_i}{\text{Uptime}_i (\text{min})}$$
The machine with $\min(\text{Throughput}_i)$ is designated as the primary production constraint.

### Q10: How does Alert Deduplication work?
**Answer:**
In continuous telemetry loops (sampling every 1–5 seconds), a fault condition (such as high tool wear) persists across dozens of ticks. Without deduplication, this would insert 60 identical alerts per minute into the database. CogniCNC maintains an in-memory hash cache of `(machine_id, alert_category) -> last_dispatched_timestamp`. If an identical alert occurs within the configured cooldown window (default: 30 seconds), the alert is suppressed and counted in `suppressed_count`, preserving database performance and preventing alarm fatigue.

### Q11: Why use SQLite in WAL mode?
**Answer:**
SQLite with **WAL (Write-Ahead Logging)** mode allows concurrent readers while a write transaction is executing. This prevents the Streamlit dashboard rendering queries from blocking continuous simulator ingestion threads.

## 5. Potential Challenging Viva Questions

### Q12: "Why didn't you predict exact Remaining Useful Life (RUL) in hours?"
**Answer:**
The **UCI AI4I 2020 dataset does not contain run-to-failure continuous degradation run logs** or true timestamped life-cycle degradation curves; it contains independent tool-wear snapshots. Predicting exact continuous RUL without run-to-failure degradation curves creates false academic certainty. Instead, CogniCNC follows defensible industrial data science practices:
1. Predicting **Failure Probability** ($P(\text{Failure}) \in [0, 1]$).
2. Estimating a **Tool Wear Life Indicator** based on the dataset's empirical tool wear threshold ($200\text{ min}$ limit).

### Q13: "How would you deploy this on a real factory floor with Siemens or Fanuc CNCs?"
**Answer:**
1. **Connectivity Layer**: Replace the `FactorySimulator` with an **OPC-UA Client** or **MQTT Edge Gateway** connected to the CNC controller (e.g., Fanuc FOCAS or Siemens Sinumerik OPC-UA Server).
2. **Edge Processing**: Deploy the `InferenceService` and `DecisionEngine` as a Docker container on an industrial IPC (e.g., Advantech or Siemens Microbox) directly on the shop floor.
3. **Database & Cloud**: Stream aggregated metrics and alerts to a central enterprise database (PostgreSQL/TimescaleDB) or cloud data lake for fleet-wide analytics.
